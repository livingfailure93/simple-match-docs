Assemblies and numbers

AssemblyNamespaceWhat it holds
SimpleMatchSimpleMatchThe core: settings, generator, rules, solver, pictures, ScriptableObjects. Pure C# apart from the ScriptableObjects, with no package dependencies, so it runs on a worker thread and in your own tests.
SimpleMatch.DemoSimpleMatch.DemoThe 3D demo (Input System, Unity UI, and HDRP when it is installed).
SimpleMatch.EditorSimpleMatch.EditorThe Match Generator window, inspectors, the documentation menu, the build look keeper.

A cell is a number: y * Width + x, with row 0 at the bottom (pieces fall toward it). A piece is an sbyte: -1 empty, otherwise its type (0 to Types - 1) in the low 4 bits and its bonus kind above them; MatchPiece reads and makes them (MatchPiece.Make(type, BonusKind.LineRow), MatchPiece.Exit for an exit piece). A solution is stored flat: a0, b0, a1, b1 ...

MatchGenerator

MemberWhat it does
GenerateVerified(settings)A puzzle that meets every hard requirement (solvable, par proven, inside the par window, on the star target, not a freebie). Tries the seed first, then seed#1, seed#2 ... up to MaxAttempts; if none works, the closest, with a note.
GenerateVerified(settings, token, limitSeconds)The same, stoppable: a cancelled CancellationToken throws OperationCanceledException, and past the limit (0 = none) a TimeoutException.
Generate(settings)One attempt with exactly this seed, sound or not.
GenerateBatch(settings, count)A set of verified puzzles with seeds seed-0, seed-1 ...
IsSound(m, settings)True when a puzzle meets the settings' hard requirements.
using SimpleMatch;

var s = new MatchSettings { Width = 7, Height = 7, Types = 4, Lines = 8, Breakables = 0.5f, TargetDifficulty = 3 };
s.Seed = "crates-1";
MatchData m = MatchGenerator.GenerateVerified(s);
Debug.Log($"{MatchAudit.Short(m)}");   // "7 x 7, clear all (4 breakables), par 4 in 4 moves, 3 stars"
foreach (var note in m.Notes) Debug.Log(note);

Generation is pure C#: run it on a worker thread (Task.Run) to keep the game responsive, as the window and the demo do. On WebGL, which has no threads, call it directly.

MatchData

One puzzle: the board, the start, the goal, the gimmicks, and what the solver proved. Plain serializable fields, so a ScriptableObject holds it. Null arrays mean "none".

FieldWhat it holds
Width, Height, TypesThe board size and how many piece types.
CellsThe piece in every cell at the start (-1 = empty).
Blocked, OutsideCells nothing enters; those outside the board's shape (the rest are obstacles, IsObstacle(cell)).
GoalA MatchGoal: ClearAll(), Collect(types, type, count), ClearLayers(), ExitAll().
Bonuses, PatternBonus pieces on, and what a Pattern clear hits.
Layers, Breakable, Fixed, Filter, Spread, Countdown, Exit, Belt, Portal, GravityThe gimmicks, one array each (index = cell). Belt and Portal hold the next cell; Gravity 0 down, 1 up, 2 left, 3 right.
Refill, DropSeed, Spawner, ExitDrops, ExitDropMaxRefill levels: on, the stream's seed, spawner cells, exit pieces that drop in.
Solvable, Complete, ParThe verdict: can it be won, did the search finish (Par proven), the fewest moves.
MoveLimitPar plus the moves to spare.
Solution, SolutionMoves()A fewest-move win (flat, or as (a, b) swaps).
Solutions, FirstMovesHow many fewest-move wins, and how many first swaps start one.
RandomWin, CarefulWin, BotWin, OddsExactThe odds the stars come from.
Difficulty1 to 5 stars (0 = the par isn't proven).
NeedsBonusesProven: plain lines alone can't reach the goal.
Seed, Settings, NotesHow it was made (the same seed and settings rebuild it exactly), and anything worth knowing about it.
Board(), Start()The board (it never changes in play) and a fresh copy of the start position, ready for MatchRules.

MatchBoard holds what never changes in play (size, types, blocked cells, filters, exits, portals, belts, gravity, spawners, bonuses on); MatchState holds what does (the pieces, layers, crates, fixed pieces, moss, countdowns, the refill stream, what has been collected). MatchState.Clone() copies a position.

Playing: MatchRules

The rules the generator and the solver use, so a game built on them always agrees with the par.

MemberWhat it does
TrySwap(board, state, a, b, out report, out reason)Make a swap and resolve every wave (cascades, bonus pieces, gimmicks, belts, moss, countdowns, refills, a reshuffle). False, with the reason in words and nothing changed, when it isn't allowed.
Refusal(board, state, a, b)Why a swap isn't allowed, or null: not neighbours, an empty or blocked cell, the same type, a fixed piece or filter, no match made.
LegalSwaps(board, state)Every allowed swap from here.
FindMatches(board, state)The groups matched right now.
Validate(m, out error)True when a puzzle's data can be played (sizes, types, every piece resting, no match at the start, a goal that fits).
MatchSolver.Met(board, state, goal, mostLeft, counts)The goal check the solver uses (mostLeft from goal.MostLeft(board, start), counts scratch of Types + 1).
MatchState.ExplodedTrue once a countdown has run out (the level is lost).
MatchBoard board = m.Board();
MatchState state = m.Start();
int[] mostLeft = m.Goal.MostLeft(board, m.Start()), counts = new int[board.Types + 1];
int moves = 0;

bool Play(int a, int b)
{
    if (!MatchRules.TrySwap(board, state, a, b, out MoveReport report, out string why)) { Debug.Log(why); return false; }
    moves++;
    if (MatchSolver.Met(board, state, m.Goal, mostLeft, counts)) Debug.Log("won");
    else if (state.Exploded || moves >= m.MoveLimit) Debug.Log("lost");
    return true;
}

Moves, waves and beats

A MoveReport says what a move did. Steps holds one CascadeStep per wave: the groups matched, the cells cleared, the bonus pieces made (Made) and fired (Fired), the layers, crates and moss hit, the exit pieces that left, the new pieces dropped in. The report also has Cleared, Combo, CascadeDepth, SpreadTo, Exploded and Reshuffled.

Set Trace before the move and Beats gets every step in order, each a MoveBeat with its Kind (Swap, Clear, Fall, Exit, Drop, Belt, Spread, Tick, Reshuffle), the pieces it moved (Moves: from, to), the cells it is about, and a copy of the position after it (After). That is what a game animates; the demo's MatchGame plays them one by one.

var report = new MoveReport { Trace = true };
if (MatchRules.Refusal(board, state, a, b) == null)
{
    MatchRules.ApplySwap(board, state, a, b, report);
    foreach (MoveBeat beat in report.Beats)
        Debug.Log($"{beat.Kind}: {beat.Moves.Count} pieces moved, {beat.Cells.Count} cells");
}

Solving and rating

MemberWhat it does
MatchSolver.Solve(board, start, goal, maxStates)The fewest moves to the goal, or proof there are none. A SolveResult: Status (Solved, Unsolvable, NotWithinLimit, OutOfBudget), Par, Moves, Solutions, FirstMoves, States, AtLeast. Puzzle mode; refill levels are proven by the generator over their stream.
MatchDifficulty.Stars(m), StarsFor(chance, scale), BandsFor(scale)The stars and the three scales' bands (StarScale Everyday, Bonus, Refill).
MatchAnalysis.RandomWin(m, plays, limit)The share of seeded random players who win within a limit (an estimate; the stamped RandomWin is exact when OddsExact).
MatchBots.HalfGreedyWin(m, plays, limit)The same for half-greedy players (what refill levels are rated on).
MatchCancel.Use(token)Make any long call (a re-solve, a Verify) stoppable on this thread: using (MatchCancel.Use(token)) MatchAudit.Verify(...).

Can it still be won?

MatchSolver.Outlook(m, state, movesMade, maxStates = 200000, board = null) answers it for any position in play, puzzle mode and refill levels alike. A MatchOutlook:

MemberWhat it holds
KindWon, CanWin, CannotWin or Unknown (the budget ran out; it is never wrong).
MovesNeeded, Moves, HintThe fewest moves still needed, one line that does it, and its first swap (a hint; auto-solve plays the line).
WhyWhy it can't be won, in the player's words: a countdown ran out, no moves left, no swap left, the goal can't be met any more, or "it needs more than the 3 moves left".
OnSolutionThe position is still on the stored solution: the answer needed no search.
MatchOutlook o = MatchSolver.Outlook(m, state, moves, 200_000, board);
if (o.Kind == OutlookKind.CannotWin) Debug.Log("This can't be won any more: " + o.Why);
else if (o.Kind == OutlookKind.CanWin && o.Hint.HasValue) Debug.Log($"hint: swap {o.Hint.Value.a} and {o.Hint.Value.b}");

It can take a moment on big refill boards, so ask it on a worker thread, as the demo does (a newer position cancels an older ask through MatchCancel).

A puzzle by hand

Fill a MatchData, check it with MatchRules.Validate, and MatchAudit.Verify solves it and stamps its par, odds and stars, as the generator would.

// 4 x 2, two types: swapping the third column's pieces makes two lines of four
var hand = new MatchData
{
    Width = 4, Height = 2, Types = 2,
    Cells = new sbyte[] { 0, 0, 1, 0,     // row 0 (the bottom)
                          1, 1, 0, 1 },   // row 1
    Goal = MatchGoal.ClearAll(),
};
if (!MatchRules.Validate(hand, out string error)) Debug.Log(error);
else
{
    MatchAudit.Verify(hand, out string before, out string after);
    Debug.Log(after);   // "4 x 2, clear all, par 1 in 1 moves, 2 stars"
}

Gimmicks are arrays of the board's size (for example hand.Fixed = new bool[8], then hand.Fixed[1] = true). The generator doesn't place portals, gravity or spawners, but the rules, the solver, the pictures and the demo all play them, so set them by hand like this.
